# Лендинг «Тренер»

Одностраничный лендинг под платный трафик: десктоп — вариант **4a**, мобильный (< 1024px) — **1c**. Сделан по handoff из `design_handoff_landing/README.md`.

**Стек:** Astro 7 + адаптер `@astrojs/vercel`: страницы собираются в статику, серверные только `/api/*` (лист ожидания и бот). Обычный CSS и немного TypeScript на клиенте. Шрифт Onest раздаётся с нашего домена (`@fontsource/onest`), картинки жмутся при сборке в AVIF/WebP. PostHog и генератор QR подгружаются, только когда нужны.

```bash
npm install
npm run dev       # http://localhost:4321 (вместе с /api)
npm run build     # → .vercel/output/
npm run check     # проверка типов
```

## Деплой на Vercel

1. Залить папку в репозиторий GitHub/GitLab → Vercel → **Add New Project** → импортировать. Фреймворк Astro определится сам, настройки сборки менять не нужно.
   Или без репозитория: `npx vercel` из папки проекта.
2. Завести бота и подключить Upstash Redis для листа ожидания (см. ниже).
3. **Settings → Environment Variables** — заполнить переменные из `.env.example` (минимум: бот, Redis и Метрика). После изменения переменных — **Redeploy**.
4. **Analytics → Enable** (Web Analytics) и **Speed Insights → Enable** — код уже подключён, без включения в панели данные просто не собираются.
5. **Settings → Functions → Function Region** — поставить Frankfurt (`fra1`): ближе к аудитории и к базе. По умолчанию функция живёт в США.
6. Свой домен: **Settings → Domains**. `og:image` и `canonical` возьмут домен продакшена сами; если нужен другой — `PUBLIC_SITE_URL`.

## Лист ожидания

Пока приложения нет в сторах, внизу вместо кнопок сторов — **«Позови в Telegram»**. Кнопка открывает бота, человек жмёт «Запустить» — и он в списке. В день релиза рассылка идёт через того же бота.

**Как это устроено.** По клику на кнопку браузер отправляет на `/api/tg-ref` выбранное в демо направление, `utm_*`, устройство и A/B-вариант под случайным ключом, а ссылка на бота получает `?start=<направление>_<ключ>` (в ссылку влезает только 64 символа, поэтому метки лежат на сервере 7 дней). Бот по `/start` достаёт их и сохраняет подписчика в Redis: только `chat_id` и источник, без имён и username. Направление записано прямо в ссылке, поэтому оно сохранится, даже если запрос с метками не дойдёт.

Бот отвечает в тоне Тренера (тексты — `BOT_COPY` в `src/content.ts`): приветствие с выбранным направлением, `/stop` — вычеркнуть, на остальное — «поговорим уже в приложении». Если человек заблокировал бота, он вычёркивается сам.

**Подключение:**

1. [@BotFather](https://t.me/BotFather) → `/newbot` → получить токен. Там же по желанию: `/setuserpic` (аватар Тренера), `/setdescription` (текст, который видят до «Запустить»).
2. Бесплатный Redis напрямую на [upstash.com](https://console.upstash.com): **Create Database** → регион Frankfurt (`eu-central-1`), план Free (256 МБ, 500 тыс. команд в месяц, карта не нужна). На странице базы, в блоке **REST API**, скопировать `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` в переменные Vercel. Один подписчик — около пяти команд, так что бесплатного тарифа хватит примерно на 100 тыс. подписок в месяц.
   Или через Vercel → **Storage → Upstash for Redis**: тогда `KV_REST_API_URL` / `KV_REST_API_TOKEN` подставятся сами, но оплата пойдёт через Vercel.
3. Переменные: `PUBLIC_TELEGRAM_BOT` (username без @), `TELEGRAM_BOT_TOKEN` → **Redeploy**. Продакшен-сборка сама подключит вебхук бота к домену продакшена (в логе сборки строка `вебхук бота: …`).
4. Уведомления о новых заявках: написать боту `/id`, полученное число положить в `TELEGRAM_ADMIN_CHAT_ID` (тип Secret) → Redeploy. Приходит только «Новая заявка · всего N» и откуда пришёл человек (`utm_source / utm_medium / utm_campaign` или «прямой заход»). Несколько админов — id через запятую.

Проверить, что всё живо: `npx vercel env pull .env`, затем `npm run tg -- info` покажет адрес вебхука, последние ошибки доставки и число подписчиков.

**Выгрузка:** задать `WAITLIST_EXPORT_PASSWORD` и открыть `https://<сайт>/api/waitlist.csv` — браузер спросит логин (любой) и пароль. В CSV оба канала, колонка `channel` (`telegram` / `email`). Разделитель `;` — файл сразу открывается колонками в Excel, в Google Таблицах тоже.

### Опрос в боте (кастдев)

Сразу после приветствия бот предлагает «пару коротких вопросов» → «Давай» / «Не сейчас». Позже — командой `/opros`. Вопросы и варианты ответов — `SURVEY` в `src/content.ts`:

1. Пробовал ли раньше взяться за свою цель
2. Что мешает дойти до конца
3. Пробовал ли трекеры
4. Мягкий или строгий тон (проверка гипотезы о тоне Тренера)
5. Что бы хотел, чтобы Тренер умел — открытый, можно пропустить

На вопросы с кнопками можно ответить и своими словами. Под отвеченным вопросом кнопки исчезают, выбранный вариант дописывается. Старые кнопки не срабатывают, недопройденный опрос забывается через неделю.

Уведомлений об ответах нет, все ответы — в выгрузке `https://<сайт>/api/survey.csv` (тот же пароль).

**152-ФЗ.** Ответы хранятся отдельно от подписки, под случайным id: без `chat_id`, имени и username. Направление и источник копируются из подписки, чтобы можно было сравнивать ответы по рекламе. Вопросов про имя, возраст, телефон и здоровье нет — не добавляйте их без юриста. Уже прошедшие опрос хранятся отдельным списком, без ответов, — чтобы не предлагать опрос дважды.

**Рассылка в день релиза:**

```bash
npx vercel env pull .env
npm run tg -- broadcast release.txt
```

Без `--send` скрипт ничего не отправляет, а только показывает текст и число получателей. С `--send` — рассылает (≈25 сообщений в секунду, лимит Telegram 30), заблокировавших бота вычёркивает из списка. Текст — обычный, ссылки Telegram сделает кликабельными сам.

### Запасная форма почты (выключена)

Под кнопкой бота может быть ссылка «Нет Telegram? Оставь почту» → форма: почта + галочка согласия на обработку ПДн. Сейчас она **выключена**: по 152-ФЗ почту при сборе надо сначала записывать в базу на территории РФ, а Vercel и Upstash — за границей. Пока `PUBLIC_WAITLIST_EMAIL` пустой, формы на странице нет и `/api/subscribe` отвечает 404.

Включить: `PUBLIC_WAITLIST_EMAIL=1` + хранилище → Redeploy. Хранилища — одно или оба:

- **UniSender** (российский сервис) — `UNISENDER_API_KEY` (Настройки → Интеграции и API) и `UNISENDER_LIST_ID`. Заявка сразу попадает в список с тегами `waitlist` и направлением. Запрос всё равно проходит через функцию Vercel — достаточно ли этого для локализации, уточните у юриста. Интеграция написана по документации API и на живом аккаунте не проверялась.
- **Upstash Redis** — тот же, что для бота.

Если подключены оба, заявка пишется в оба; ошибка — только если не записалось никуда. Повторная заявка с той же почтой не перетирает первую. Защита от мусора: скрытое поле-ловушка, не больше 30 заявок в час с одного IP (IP хранится только хешем и час), POST с чужого домена Astro отклоняет сам. Без JS форма тоже работает. Если бот не настроен, а почта включена, форма встаёт на место кнопки.

Локально без переменных заявки с почты не сохраняются, а только печатаются в консоль `npm run dev`.

**На релизе:** `PUBLIC_CTA_MODE=stores` + ID сторов → Redeploy. Вернутся кнопки, бейджи, QR-модалка и `/go` (в режиме листа ожидания `/go` ведёт на главную). Потом — рассылка через бота.

## Ссылки на стор (режим `stores`)

- **Телефон:** главная кнопка и бейдж ведут прямо в стор своей ОС (или в смарт-ссылку, если задана). Показывается только бейдж текущей ОС.
- **Десктоп:** главная кнопка открывает модалку с QR-кодом + бейджи обоих сторов (открываются в новой вкладке).
- **`/go`** — своя «смарт-ссылка» без MMP. На неё ведёт QR, если `PUBLIC_SMART_LINK` пуст: телефон сразу уходит в свой стор, десктоп видит выбор.
- **Google Play** получает `referrer` с `utm_*` и направлением — приложение читает его через Install Referrer API.
- **App Store** получает `pt` + `ct` (кампания, до 40 символов) — видно в App Store Connect → App Analytics.
- **OneLink:** если смарт-ссылка на `*.onelink.me`, UTM дублируются в параметры AppsFlyer (`pid`, `c`, `af_ad`, `af_keywords`), направление — в `deep_link_value`.

**Направление из демо** уходит параметром `direction=<sport|money|focus|health>`, а не в `utm_content`, как было в handoff. Причина: `utm_content` уже несёт креатив, и если его перезаписать, установка теряет привязку к объявлению. Приложению нужно читать `direction` (из referrer на Android и из `deep_link_value` / параметров смарт-ссылки). Имя параметра — одна константа `DIRECTION_PARAM` в `src/scripts/links.ts`.

UTM и click id (`yclid`, `fbclid`, `ttclid`, `rb_clickid`, `gclid`) сохраняются в `sessionStorage` при заходе и дописываются во все ссылки на стор.

## Аналитика

Все события идут через одну функцию `track()` в `src/scripts/analytics.ts`, к каждому автоматически добавляются `utm_*`, click id, `device` (ios/android/desktop), `variant` (desktop_4a / mobile_1c), `ab` и `direction` (если выбрано).

| Событие | Когда | Параметры |
|---|---|---|
| `page_view` | загрузка | referrer |
| `scroll_depth` | 25 / 50 / 75 / 100% | depth |
| `section_view` | секция ≥ 50% в кадре впервые | section: hero, screens, video, demo, cta |
| `dialog_start` | кнопка «Ну и как это выглядит?» — дальше разговор идёт сам | — |
| `screenshot_view` | скрин в кадре / свайп | index |
| `video_play` | первый старт | autoplay |
| `video_progress` | 25 / 50 / 75 / 100% | percent |
| `video_unmute` | включил звук | — |
| `direction_click` | выбор направления | direction |
| `tg_click` | кнопка «Позови в Telegram» | — |
| `waitlist_start` | первый фокус в форме почты | — |
| `waitlist_signup` | заявка сохранена | — |
| `waitlist_error` | заявка не прошла | reason: invalid / consent / rate / server / network |
| `cta_click` | главная кнопка (режим stores) | position: final |
| `store_click` | бейдж стора (режим stores) | store: ios / android |
| `qr_shown` | модалка с QR (режим stores) | — |
| `time_on_page` | 15 / 30 / 60 с активного времени | seconds |

Куда уходит:

- **Яндекс Метрика** — все события как цели `reachGoal`, `page_view` — в параметры визита. `section_view` уходит целями `section_view_hero`, `section_view_screens` и т. д. (Метрика не умеет фильтровать цель по параметру, а для воронки нужны отдельные шаги). Вебвизор, карта кликов, точный показатель отказов включены в коде; карту скроллинга включить в настройках счётчика.
  В интерфейсе Метрики создать цели типа «JavaScript-событие» с идентификаторами: `dialog_start`, `tg_click`, `direction_click`, `section_view_screens`, `section_view_demo` (+ остальные по желанию; если включена почта — `waitlist_start`, `waitlist_signup`; на релизе — `cta_click`, `store_click`, `qr_shown`). Воронка — составная цель: `dialog_start` → `section_view_screens` → `section_view_demo` → `direction_click` → `tg_click` (на релизе последний шаг — `store_click`). Нажатие «Запустить» происходит уже в Telegram, Метрика его не видит — реальное число подписчиков показывает бот (уведомления, `npm run tg -- info`, CSV).
- **PostHog** — все события, `page_view` как `$pageview`. Воронки строятся по `section_view` с фильтром по `section`.
- **Пиксели** (Meta / TikTok / VK) — только `direction_click`, `tg_click`, `waitlist_signup`, `cta_click`, `store_click`, `qr_shown` + просмотр страницы. Переход в бота и заявка с почты уходят стандартным событием — `Lead` в Meta, `SubmitForm` в TikTok, — на них можно оптимизировать кампании.
- **Vercel Web Analytics** — просмотры, источники, страны, устройства на любом плане. Кастомные события (те же, что в пиксели) Vercel принимает только на Pro; на Hobby они просто не сохраняются.

Сторонние скрипты грузятся после `load`, чтобы не мешать первому экрану. Переход в стор ждёт отправки цели не дольше 300 мс.

**Отладка:** на `localhost` или с `?debug_analytics` в адресе каждое событие пишется в консоль.

### Согласие на cookie

Баннер появляется, только если подключено что-то с cookie (Метрика, PostHog, пиксели); Vercel Analytics работает без cookie.

- `PUBLIC_CONSENT_MODE=notice` — аналитика стартует сразу, баннер уведомляет («Понятно»). Типичная практика для РФ.
- `PUBLIC_CONSENT_MODE=opt-in` — Метрика, PostHog и пиксели ждут «Принять». Нужно, если есть трафик из ЕС.

Какой режим нужен по 152-ФЗ именно вам — вопрос к юристу; код поддерживает оба.

## A/B

Тексты с атрибутом `data-copy` (например, главная кнопка) подменяются вариантом из `AB_VARIANTS` в `src/content.ts`. Вопрос и «Я знаю секрет» на первом экране нарисованы на картинке и через A/B не меняются — только скрытый `h1` для поиска:

```ts
export const AB_VARIANTS = {
  b: { tgButton: '…', ctaMain: '…' },
};
```

Ссылка `?v=b` включает вариант (он запоминается на сессию), ключ уходит во все события параметром `ab`. Подменить можно любой элемент с атрибутом `data-copy`. Для раскатки через PostHog feature flags — читать флаг и класть его значение в тот же механизм.
